# levelgx — prove a level is playable

Part of the `gxkit` family; the review contract is shared with every `*gx` tool.

## Install

```sh
uvx --from "git+https://github.com/nekomario28/gxkit#subdirectory=packages/levelgx" levelgx --help
uv tool install ./packages/levelgx
```

## Write a level

```python
NAME = "First room"
rows = [
    "#########",
    "#S......#",
    "#.#####.#",
    "#X....#G#",
    "#########",
]
```

Legend: `#` wall, `.`/space floor, `S` spawn, `G` goal, `X` item, `!` hazard,
`>` `<` `^` `v` one-way tiles.

## The loop

1. Write the level as a Python file.
2. `levelgx inspect level.py` — size, reachability, shortest path, problems with
   stable `code`s, and `<name>.storyboard.png`. **Exit 1 on any error.**
3. Fix and inspect again; the storyboard boxes each problem cell.
4. `levelgx render level.py -o level.png`.

## Severities

`error` = broken (no spawn/goal, unreachable goal, soft-lock, stranded item).
`warn` = a hazard blocks the only route. `info` = dead space, or no items.

## Why it can be trusted

`soft-lock` is the check reachability cannot make. A one-way tile makes the
level a directed graph, so a cell can be reachable while the goal is not
reachable *from* it — the player is trapped. The tool searches the directed
graph for those cells. Every check has a test that proves it fires on a level
with the defect and stays quiet on one without (`tests/`).
