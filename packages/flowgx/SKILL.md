# flowgx — prove a state machine can finish

Part of the `gxkit` family; the review contract is shared with every `*gx` tool.

## Install

```sh
uvx --from "git+https://github.com/nekomario28/gxkit#subdirectory=packages/flowgx" flowgx --help
uv tool install ./packages/flowgx
```

## Write a machine

```python
import flowgx as f

machine = f.Machine(
    states=["draft", "review", "published"],
    start="draft",
    accept=["published"],
    transitions=[
        ("draft", "review", "submit"),
        ("review", "published", "approve"),
    ],
)
```

Or module-level `STATES` / `TRANSITIONS` / `START` / `ACCEPT`. Transitions are
`(source, target)` or `(source, target, event)`.

## The loop

1. Write the machine as a Python file.
2. `flowgx inspect machine.py` — states, accepting states, cycle, problems with
   stable `code`s, and `<name>.storyboard.png`. **Exit 1 on any error.**
3. Fix and inspect again; the storyboard boxes each faulty state.
4. `flowgx render machine.py -o machine.png`.

## Severities

`error` = the flow is broken. `info` = a cycle exists (keep it if intended).

## What it catches

| code | severity | meaning |
| --- | --- | --- |
| `no-start` | error | no start state |
| `no-accept` | error | "done" is undefined |
| `unknown-state` | error | a transition names an undeclared state |
| `unreachable-state` | error | a state cannot be reached from the start |
| `dead-end` | error | a reachable state has no way out and is not accepting |
| `no-exit` | error | a reachable state can never reach "done" |
| `ambiguous-transition` | error | two transitions from one state share an event |
| `cycle` | info | a loop exists; one finding per cyclic component |
| `clipped-text` | error | a state label is cut off by the canvas |
| `text-overlap` | error | two state labels overlap |
| `small-text` | info | a label is below the readable floor |

`no-exit` is the workflow form of a soft-lock: the state is reachable but "done"
is not reachable from it. `gxcore.graph` computes it with reverse reachability.

Every check has a test that proves it fires on a machine with the fault and stays
quiet on one without (`tests/`).
